# 本地选择器架构

原生入口→主程序→来源选择→解析/验证→业务规则→生成新快照→系统保存→
输出比较→独立重新选择文件→全文比较→报告成功。

local_storage.py 只生成原生动作。state_v2.py 是开发参考模型，不在手机执行。
native_manager.py 的 evaluate/stats 复用原规则。完整动作参数组合仍待实机验证。
数据v2保留v1顶层和 records 字典，新增 app_version、created_at、revision。
每次写入 revision+1、更新 updated_at，另存 state-rN-时间戳.json。
旧状态不被修改，可回滚；手动备份另存独立副本。不要求固定 backup/pending 文件名。
新快照读回前是候选，读回后由用户下次选择；没有原子提升和主指针。

首次安装需明确确认，不能自动扫描所有位置区分缺失；读失败不会初始化。
恢复直接选择备份，不先解析损坏主文件；校验、预览、二次确认后另存。
时间含时区，周/日归属沿用当前设备日历，旅行变更时区可能改变历史统计。
历史限制20年；拒绝未来饮用/打卡、打卡早于饮用、截止超48小时、同周多条记录。
单次运行限制不能防止用户选择旧文件形成分支；无事务锁、分支合并或无交互权限保证。
